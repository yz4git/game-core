## Observations → Mechanisms → Generalized Principles → Transfer → Playtest Question

### 1. Geometric difference is not gameplay difference
**Observation:** Two generated levels can have different tiles/shapes while an agent solves them with nearly the same action sequence.
**Mechanism:** Surface variation does not necessarily alter decisions.
**Generalized Principle:** Measure diversity in behavior/decision space as well as asset/layout space.
**Transfer:** Store canonical agent trajectories and compare action-sequence edit distance across seeds.
**Playtest Question:** Do visually different seeds actually require different routes, timing, resources or priorities?

### 2. Decision signatures are stronger than screenshot uniqueness
**Observation:** Simulation-based work can compare levels through trajectories rather than visual representation.
**Mechanism:** Agent behavior compresses the mechanically relevant constraints of a level.
**Generalized Principle:** A procedural QA signature should include what a competent player must do, not only what the level looks like.
**Transfer:** Signature = route turns + jump/attack/boost events + resource use + hazard exposure + branch choices.
**Playtest Question:** How many seeds collapse to the same normalized decision signature?

### 3. Diversity needs distribution coverage, not maximum pairwise novelty
**Observation:** Expressive Range Analysis studies coverage/density/clusters in descriptor space.
**Mechanism:** A generator may produce a few extreme outliers while most seeds cluster tightly.
**Generalized Principle:** Evaluate the distribution of generated content, not cherry-picked examples or only min/max values.
**Transfer:** Plot thousands of seeds in 2–4 gameplay descriptors and track occupied bins, entropy, dense clusters and outliers.
**Playtest Question:** Are 80% of production seeds concentrated in one small behavioral region?

### 4. Quality metrics are proxies, not replacements for people
**Observation:** Empirical Mario-level research found computational metrics do not fully substitute for user studies.
**Mechanism:** Numeric descriptors miss perceptual rhythm, surprise, frustration and semantic meaning.
**Generalized Principle:** Automated metrics should filter and diagnose; human playtests calibrate whether metrics predict experience.
**Transfer:** Periodically correlate automated scores with blind human ratings and retire misleading metrics.
**Playtest Question:** Which automated metric actually predicts perceived repetition or difficulty for this game?

### 5. Generic metrics should map to design patterns
**Observation:** Cross-genre research quantified patterns such as exploration, area control and balance.
**Mechanism:** Design-pattern metrics abstract above raw tile representation.
**Generalized Principle:** Prefer metrics tied to player problems over engine-specific geometry counts.
**Transfer:** Examples: route alternatives, contested-space balance, exploration detour value, safe-area ratio, landmark reachability.
**Playtest Question:** Can the metric be explained as a player decision rather than a rendering statistic?

### 6. Route heatmaps reveal invisible generator bias
**Observation:** Repeated agent traces expose where generated routes actually concentrate.
**Mechanism:** Nominally open spaces can funnel optimal/viable play through the same corridor topology.
**Generalized Principle:** Aggregate behavior spatially to find structural sameness that individual maps hide.
**Transfer:** Rasterize normalized route occupancy across seeds; flag cells/regions with persistent dominance.
**Playtest Question:** Does the generator offer multiple paths on paper but repeatedly force the same practical line?

### 7. Difficulty should be decomposed into search and execution
**Observation:** Search-tree expansion can estimate how difficult a level is for a planning agent, but execution difficulty may differ.
**Mechanism:** Finding a solution and performing it are different burdens.
**Generalized Principle:** Procedural difficulty metrics need separate planning, precision, timing and resource dimensions.
**Transfer:** Record search expansions, minimum timing margin, required input density and resource slack separately.
**Playtest Question:** Is a seed hard because the route is difficult to discover or because execution tolerance is narrow?

### 8. Novelty objectives need quality gates
**Observation:** Novelty search can increase diversity, while evolutionary work also shows fitness functions can miss actual playability.
**Mechanism:** Optimizing novelty alone rewards unusual failure states as readily as useful variation.
**Generalized Principle:** Diversity optimization must occur inside a validated playable/quality envelope.
**Transfer:** Hard gates: reachable, no invalid geometry, resource-feasible; then optimize novelty among survivors.
**Playtest Question:** Are the most novel seeds genuinely playable or merely broken in new ways?

### 9. Visual semantic diff should compare regions by role
**Observation:** Human similarity judgments do not align perfectly with generic tile/image distance metrics.
**Mechanism:** Players weight semantically important structures differently from cosmetic pixels.
**Generalized Principle:** Visual repetition detection should use role-aware features, not one whole-frame hash.
**Transfer:** Compare skyline, road silhouette, landmark placement, biome palette class, room topology and encounter silhouette separately.
**Playtest Question:** Do two screenshots hash as different only because foliage/noise changed while their memorable structure is identical?

### 10. Perceptual hashes are useful only as a first-pass duplicate detector
**Observation:** Perceptual hashing detects near-image similarity but is insensitive to gameplay semantics and viewpoint changes.
**Mechanism:** Low-dimensional image fingerprints capture appearance, not meaning.
**Generalized Principle:** Use pHash/dHash as cheap screening, followed by semantic/layout/behavior checks.
**Transfer:** CI can flag near-duplicate canonical screenshots, then inspect structural descriptors before rejecting a seed.
**Playtest Question:** Are false positives/negatives concentrated around lighting, camera or animated effects?

### 11. Canonical cameras make visual regression measurable
**Observation:** Visual comparison becomes unstable when camera pose, time, weather and animation vary.
**Mechanism:** Uncontrolled presentation variance overwhelms generator variance.
**Generalized Principle:** Procedural visual QA needs deterministic observation points.
**Transfer:** For every seed render fixed spawn/landmark/route checkpoints with locked camera, FOV, time and weather.
**Playtest Question:** Can the same seed/build reproduce the same QA views closely enough for meaningful diffing?

### 12. Worst-N seeds are more useful than averages for production QA
**Observation:** A generator can score well on average while rare catastrophic seeds remain shippable.
**Mechanism:** Tail failures disappear in means.
**Generalized Principle:** Procedural QA must inspect distribution tails and preserve failing seeds as fixtures.
**Transfer:** Track p95/p99/worst-N for route length, slope, dead ends, performance, repetition and difficulty.
**Playtest Question:** What are the ten worst currently valid seeds and why did they survive the gates?

### 13. Generator changes need distribution regression, not only seed regression
**Observation:** Fixed canonical seeds catch deterministic breakage but can miss population-level drift.
**Mechanism:** A code change can leave known seeds valid while shifting probabilities across the entire generator.
**Generalized Principle:** Test both fixed fixtures and fresh large samples.
**Transfer:** Compare descriptor histograms between generator versions using stable seed sets plus new random cohorts.
**Playtest Question:** Did this update quietly make common worlds flatter, easier or more repetitive?

### 14. Diversity has a useful minimum and a dangerous maximum
**Observation:** Extreme novelty can weaken learned grammar and player prediction.
**Mechanism:** Players need recurring structure to transfer knowledge between generated instances.
**Generalized Principle:** Optimize for bounded expressive range: enough variation to change decisions, enough recurrence to support mastery.
**Transfer:** Define target bands for descriptors rather than maximizing entropy without limit.
**Playtest Question:** Can players reuse learned rules across seeds while still encountering new decisions?

## Implementation-ready QA pipeline

1. Generate canonical + random seed cohorts.
2. Hard invariants: reachability, intersections, slopes, collision, spawn clearance, resource feasibility.
3. Run one or more deterministic agents and capture traces.
4. Derive decision signatures and route heatmaps.
5. Compute descriptor-space coverage/density/outliers.
6. Render deterministic canonical views.
7. Cheap visual near-duplicate pass (pHash/dHash), then semantic-region descriptors.
8. Rank worst-N and novelty outliers for human review.
9. Compare distribution against previous generator version.
10. Periodically calibrate metrics against human playtest ratings.

## Suggested CI artifacts

- seed + generator version
- invariant failures
- agent trace and route occupancy
- decision signature
- descriptor vector
- canonical screenshots
- visual similarity neighbors
- performance timing
- quality/novelty classification
- nearest historical failing fixture

This makes a failure reproducible rather than merely reporting that a batch looked repetitive.
