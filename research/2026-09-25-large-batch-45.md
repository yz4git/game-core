# Large Batch 45 — Metamorphic Procedural QA

Date: 2026-09-25

## Scope
This batch extends adversarial procedural QA with **metamorphic testing**: when a single generated level/world has no unique expected output, test relationships that should hold across controlled transformations of the same valid parent.

Historical comparison set: Gaming Alexandria-preserved Micom BASIC / Program Pochette material across the 1980s and later indexed holdings, sampled across shooters, maze/pursuit games, racing/action, finite-resource games and puzzles. Modern comparison set: property-based / coverage-guided testing, metamorphic testing, adaptive operator selection, and quality-diversity testing literature.

No magazine prose, page images, or close paraphrases are stored here.

## New observations

### 1. Correctness can be relational when no golden output exists
**Observation:** Procedural worlds often have many valid outputs, so pixel- or layout-exact golden answers are inappropriate.
**Mechanism:** A controlled transformation can define an expected relation even when neither output has a unique expected value.
**Generalized Principle:** Specify invariants between sibling cases, not only expected values for isolated cases.
**Transfer:** Generate a valid parent, transform one semantic factor, then compare gameplay descriptors.
**Playtest Question:** Which properties should remain invariant when this factor changes?

### 2. Cosmetic transformations should preserve game truth
**Observation:** Art, lighting, decoration, or non-colliding dressing changes can accidentally alter navigation/collision through pipeline coupling.
**Mechanism:** Asset regeneration may touch semantic buffers that were intended to remain unchanged.
**Generalized Principle:** Cosmetic-only transformations require PRESERVE contracts for collision, nav connectivity, timing and rules.
**Transfer:** Compare semantic hashes before/after cosmetic regeneration.
**Playtest Question:** Did anything about the player's legal decisions change when only presentation was supposed to change?

### 3. Difficulty transformations need directional contracts
**Observation:** Increasing an intended pressure variable does not require a known final difficulty score.
**Mechanism:** Expected direction can still be specified for reaction slack, resource slack or safe-space.
**Generalized Principle:** Use MONOTONIC contracts for intentionally ordered gameplay changes.
**Transfer:** Increase enemy pressure while holding topology constant and assert that the selected pressure margin does not improve beyond tolerance.
**Playtest Question:** Did the supposedly harder sibling accidentally become easier through an interaction?

### 4. Same-parent siblings reduce seed noise
**Observation:** Comparing unrelated seeds confounds the transformation with unrelated topology/content differences.
**Mechanism:** Common ancestry cancels much of the generator variance.
**Generalized Principle:** Counterfactual QA should prefer sibling worlds derived from one parent.
**Transfer:** Store parent ID, transformation ID and semantic delta.
**Playtest Question:** Can a player attribute the outcome change to the tested transformation rather than a different layout?

### 5. Repair can invalidate the metamorphic hypothesis
**Observation:** Validity-preserving repair may modify the very variable whose effect is being tested.
**Mechanism:** The repaired child becomes a different experiment.
**Generalized Principle:** Reject or downgrade evidence when repair intersects the hypothesis footprint.
**Transfer:** Track repair domains and compare them with protected transformation domains.
**Playtest Question:** Did repair restore legality without erasing the intended experimental difference?

### 6. Round trips expose persistence and generator drift
**Observation:** Serialize/reload, export/import, or representation conversions can remain syntactically valid while changing game semantics.
**Mechanism:** IDs, defaults, ordering, precision or missing fields can alter reconstructed state.
**Generalized Principle:** ROUND_TRIP contracts should compare semantic state, not byte identity alone.
**Transfer:** Compare topology, critical entity identities, progression flags, RNG provenance and gameplay descriptors after round trip.
**Playtest Question:** Does the reconstructed world offer the same meaningful decisions?

### 7. Symmetry is useful only where the design promises symmetry
**Observation:** Mirroring a map can reveal hidden directional bias, but some games intentionally break symmetry.
**Mechanism:** Camera, handedness, spawn rules, lighting or AI may create unintended asymmetry.
**Generalized Principle:** Apply SYMMETRY contracts only to declared symmetric contexts and measure allowed deviation.
**Transfer:** Mirror geometry/input/spawns together and compare outcome distributions.
**Playtest Question:** Is any advantage caused by intentional design or an implementation artifact?

### 8. Permutation tests catch hidden ordering dependencies
**Observation:** Reordering semantically unordered objects can change results through iteration order, IDs or floating-point accumulation.
**Mechanism:** Implementation order leaks into simulation truth.
**Generalized Principle:** PERMUTATION contracts are valuable for unordered collections and deterministic simulation.
**Transfer:** Shuffle equivalent spawn lists, entity serialization order or generation passes while preserving declared semantics.
**Playtest Question:** Does a harmless ordering change alter difficulty or outcome?

### 9. Policy ordering is stronger than one-agent success
**Observation:** A generator may pass with one bot while violating the intended skill structure.
**Mechanism:** Exploit policies can outperform competent policies when generated geometry exposes unintended shortcuts.
**Generalized Principle:** Test POLICY_ORDER relations across novice/baseline/expert/exploit agents.
**Transfer:** Flag reversals such as exploit >> expert or novice consistently outperforming baseline in skill-dependent tasks.
**Playtest Question:** Does the generated content reward the skills the game claims to test?

### 10. Temporal transformations need bounded rather than exact relations
**Observation:** Small timing changes can cause chaotic downstream differences even when behavior remains acceptable.
**Mechanism:** Dynamic systems amplify phase differences.
**Generalized Principle:** Use BOUNDED contracts for time-sensitive systems instead of exact trajectory equality.
**Transfer:** Compare completion bands, damage ranges, encounter ordering and margin envelopes.
**Playtest Question:** Is the variation within an acceptable behavioral envelope?

### 11. Metamorphic failures should shrink as pairs
**Observation:** Shrinking only the failing child can destroy the relation that made the bug meaningful.
**Mechanism:** The failure exists in the difference between parent and child.
**Generalized Principle:** Minimize the transformation pair while preserving both validity and the violated relation.
**Transfer:** Shrink parent content and transformation delta jointly.
**Playtest Question:** What is the smallest valid sibling pair that still flips the expected relation?

### 12. Metamorphic relation selection is itself an adaptive search problem
**Observation:** Not every relation is equally informative in every behavior region.
**Mechanism:** Context determines whether symmetry, monotonicity, round-trip or policy-order checks are likely to expose faults.
**Generalized Principle:** Allocate relation-testing budget using historical yield while retaining an exploration floor.
**Transfer:** Track relation × behavior-region × generator-epoch yield, severity and compute cost.
**Playtest Question:** Which relation currently finds new actionable failures rather than repeatedly rediscovering the same family?

## Contract vocabulary

Use a small explicit vocabulary:
- **PRESERVE** — semantic property should not change.
- **MONOTONIC** — property should move in a declared direction.
- **BOUNDED** — change must remain inside an allowed envelope.
- **ROUND_TRIP** — encode/decode or export/import preserves semantics.
- **PERMUTATION** — reordering unordered inputs preserves semantics.
- **SYMMETRY** — declared symmetric transformation preserves equivalent opportunity.
- **POLICY_ORDER** — expected relative ordering among player/agent policies is preserved.

## Production pipeline

`VALID PARENT -> CHOOSE RELATION -> CONTROLLED TRANSFORM -> VALIDITY CHECK -> BOUNDED REPAIR -> HYPOTHESIS-FOOTPRINT CHECK -> RUN SIBLINGS -> RELATION EVALUATION -> HUMAN TRIAGE IF NOVEL/SEVERE/UNCERTAIN -> PAIRED SHRINK -> REGRESSION FIXTURE`

## Telemetry
Record:
- parent / child IDs and generator epoch
- relation type and protected semantic domains
- transformation delta
- repair delta and overlap with hypothesis footprint
- descriptor/margin vectors before and after
- policy outcomes
- violation magnitude
- failure signature
- human confirmation / false-positive label
- compute cost and time-to-first violation

## Implementation consequence
Metamorphic QA complements canonical fixtures, unbiased random sampling, adversarial mutation and human playtesting. It does not replace them. Its main value is converting “there is no single correct generated world” into testable statements about **how valid worlds should relate under controlled change**.
