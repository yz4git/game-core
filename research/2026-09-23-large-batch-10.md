# Key synthesis

## Rhythm timing
- 音声時刻を判定の権威にし、描画を追従させる。
- 環境ごとの遅延を校正可能にする。
- Early/Lateを学習フィードバックとして使う。
- 入力装置の応答性も公平性の一部。

## Strategy UI
- micro / local / macro を短い視線移動で往復させる。
- 頻繁に一緒に使う情報を画面端へ散らさない。
- 可視UIとホットキーを初心者→熟練者の同一路線にする。
- 通知は出来事数ではなく対応緊急度で優先する。

## Inventory / Crafting
- 選択は残し、検索・整理・明白な反復作業を自動化する。
- アイテム量に検索能力を比例させる。
- レシピは一度に大量開示しない。
- 素材と工程を論理的にして外部Wiki依存を減らす。

## Camera
- キャラ中央ではなく「次の判断に必要な情報」を映す。
- 高速時は未来情報を多く見せる。
- 壁回避より対象可視性を優先する。
- 自動カメラにレベル側の例外指定を持たせる。

## Local multiplayer
- 部屋の中の会話・ブラフ・笑いをゲーム状態として扱う。
- 敗者の待ち時間を短くする。
- 観戦者にも状況を読みやすくする。
- 共有画面の境界を協力ルールとして利用する。

## Procedural generation
- feasible / interesting / appropriate difficulty を同時に満たす。
- 最低品質を検査し、不合格seedを出さない。
- seed + generator versionで再現可能にする。
- 難易度はランダムではなく制約の段階で作る。
- player capability と generator を共同設計する。

## Accessibility
- 難易度を reaction / precision / vision / hearing / memory / strategy に分解する。
- Assistは困難要因だけを緩め、中心技能をできるだけ残す。
- 重要情報を複数感覚チャンネルで冗長化する。
- preset + granular optionsを両立する。

## Rewards without grind
- 外的報酬が内的動機を置き換えないようにする。
- 固定報酬と変動報酬の役割を分ける。
- 休んだ罰より戻る価値を中心にする。
- デイリー課題がプレイヤーの自由目標を奪わないようにする。
