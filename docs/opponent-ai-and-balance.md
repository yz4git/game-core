# Opponent AI & Perceived Balance

CPU・敵AIを「強くする」だけでなく、読める・公平・学習可能・再戦したくなる相手にするための設計メモ。

## 1. AIはコア設計の一部

AIが主要体験なら、ステージ完成後に足さない。

最初に決める:
- AIが見える情報
- AIが見えない情報
- 記憶時間
- 意思決定頻度
- 状態遷移
- 候補行動
- リスク評価
- プレイヤーへの反応

## 2. Player-readable intelligence

賢さを「予測不能」と同一視しない。

理想:
- 初見では少し読みにくい
- 数戦すると傾向が見える
- 上級者は誘導できる
- ただし完全固定ではない

## 3. Bounded variation

同じ状態でも複数の妥当行動を持たせる。

例:
- 接近 50%
- 様子見 30%
- 回り込み 20%

重みは、
- 距離
- HP
- プレイヤー行動履歴
- 地形
- 味方状態
で変える。

完全ランダムではなく、理由のある揺らぎにする。

## 4. Anti-pattern memory

プレイヤーが同じ行動を繰り返す場合、AIが少しずつ対応を変える。

ただし即座に完全対策すると「入力を読んでいる」ように感じる。

段階例:
1. 気づかない
2. 警戒する
3. 対策を混ぜる
4. 明確な対策を使う

## 5. Information fairness

CPUが人間より多くの情報を持つ場合、目的を明確にする。

許容しやすい例:
- 処理負荷を抑えるため
- 人間の視覚・記憶を近似するため
- 弱いAIを補うため

危険:
- 壁越しに常時追跡
- 未発見情報を利用
- 入力直後に完璧反応
- 乱数結果を事前に知る

## 6. Perceived balance

勝率50%だけでは公平性を測れない。

観察する:
- 負けた理由を説明できるか
- CPUがズルしたと感じるか
- 勝利が自分の工夫に見えるか
- 敗北後に別戦術を試したくなるか

## 7. Asymmetric objectives

非対称な陣営は、同じ資源・能力を持つ必要はない。

代わりに、
- 勝利条件
- 制限時間
- 生存条件
- 得点条件
を役割ごとに調整する。

## 8. Exploit test

AIレビューでは必ず「壊しに行く」。

試す:
- 端へ誘導
- 同じ攻撃連打
- 遠距離固定
- 高低差
- 障害物越し
- 待ち
- リセット誘発
- ターゲット切替
- 複数敵同士の干渉

## 9. Difficulty scaling

Hard AIを作るとき、
- 反応速度だけ上げない
- 入力読みを増やさない
- ダメージ倍率だけにしない

代わりに、
- 選択肢の質
- コンボの組み立て
- 位置評価
- リソース管理
- プレイヤー傾向への適応
を少しずつ改善する。

## 10. Debug visibility

開発中はAIの内部状態を表示できるようにする。

例:
- target
- state
- chosen action
- action weights
- danger score
- remembered player action
- path target

「なぜそう動いたか」を説明できないAIは調整しにくい。
