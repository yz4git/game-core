# Fighting Game Design

対戦格闘を「技の数」ではなく、状態遷移・間合い・対抗策・学習で設計するためのガイド。

## 1. Neutral / Advantage / Disadvantage

一瞬一瞬を「どちらが次の行動を通しやすいか」で見る。

- Neutral: 両者が位置・技・タイミングを探る
- Advantage: 片方が安全に選択を押し付けやすい
- Disadvantage: 防御・回避・読みで戻す必要がある

攻撃ヒットはダメージだけでなく、次にどの状態へ移るかまで設計する。

## 2. Move value = immediate result + future state

技ごとに記録する。

- 発生
- 到達距離
- リスク
- ダメージ
- 終了位置
- ヒット後の距離
- ガード後の距離
- 主導権
- 資源変化

高威力でも不利になる技、低威力でも位置を奪う技があると選択が増える。

## 3. Counterplay

強い戦法には対策を用意する。

良い対策:
- 観察で存在を推測できる
- 実行難度が強さに見合う
- 成功すると主導権が変わる

避ける:
- 特定の隠し入力を知らないと無理
- 一人だけ万能な正解技を持つ
- 対策しても状況が改善しない

## 4. Throws / strikes / defense

投げ・打撃・防御は単純な三すくみに固定しない。

距離、遅らせ、移動、空振り、資源を絡める。

投げ後の左右・距離・起き上がり位置も次の読み合いを作る重要な結果。

## 5. Matchup matrix

キャラクターごとではなく組み合わせごとにテストする。

| 観点 | 記録 |
|---|---|
| 得意距離 | どこで各キャラが強いか |
| 接近方法 | 不利側がどう距離を詰めるか |
| 逃げ方法 | 有利側からどう離れるか |
| 反撃 | 何を見て返せるか |
| 資源 | どちらが何を溜めやすいか |
| 端 | 画面端で関係がどう変わるか |

## 6. Training

技表だけでなく状況を練習できるようにする。

- 対空
- ガード後反撃
- 投げ対策
- 起き上がり
- 画面端
- 特定技への回答
- 特定距離での差し合い

実戦で失敗した場面を数秒で再現できることを重視する。

## 7. Beginner path

初心者には、
1. 移動
2. 通常攻撃
3. 防御
4. 一つの対空
5. 一つの確定反撃
を先に体験させる。

複雑なコマンド入力を戦略理解より先に要求しすぎない。

## 8. CPU vs human

CPU戦では反応速度で勝たせない。

CPUは、
- 読める癖
- 複数候補からの選択
- 難易度ごとの判断精度
を持つ。

対人戦では、技性能よりプレイヤー同士の適応が中心になるため、CPU向けの「正解」をそのまま対人バランスへ使わない。

## 9. Playtest questions

- 強い技の後に明確な対抗策があるか
- 投げ後の位置に意味があるか
- キャラを替えると得意距離が変わるか
- 同じ戦法を3回見せた相手が次を予測できるか
- 技入力の難度が読み合いを隠していないか
- 画面端が単なる即死ゾーンになっていないか
