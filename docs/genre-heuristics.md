# Genre Heuristics

ジャンルごとに特に重要になる観点。絶対ルールではなく、レビュー時の重点項目。

## Action / Combat

- 攻撃・回避・防御が三すくみではなく状況で使い分けられるか
- 敵の予告が反応可能か
- 成功すると主導権が変わるか
- 常に安全な万能行動がないか
- 被弾理由が読めるか
- ヒット確認と空振り確認ができるか

### Parry-centered combat

パリィを単なる「高性能ガード」にしない。

成立させる要素:
- 明確だが簡単すぎない予告
- 失敗リスク
- 成功時の主導権変化
- 回避を選ぶべき攻撃
- パリィ不能／遅らせ攻撃などの読み合い
- 上級者向けの早取り・連続成功などの第二目標

## Racing / Driving

- 最速ラインと安全ラインが分かれるか
- ブレーキが失敗修正だけでなく戦略になるか
- 速度感と操作精度が両立しているか
- 接触・破壊がレース判断へ影響するか
- ライバル車が単なる障害物になっていないか
- コース記憶が上達につながるか

## Shooter

- 弾幕量ではなく安全地帯の読みがあるか
- 敵撃破の優先順位が変わるか
- 射撃と移動が相互作用しているか
- 敵配置がプレイヤーを動かしているか
- 武器差がDPS差だけになっていないか
- ボスで道中の学習を試しているか

## Roguelike / Procedural

- ランダムが問題を変え、勝敗を直接決めていないか
- 毎回ビルド方針が変わる選択があるか
- 小さな選択が後の状況へつながるか
- ハズレ生成でも最低限の面白さを保証できるか
- プレイヤーがランダムを読む／制御する手段があるか

## Puzzle

- 正解を知る前に考える材料が見えているか
- 試行錯誤のコストが高すぎないか
- 新ルールが既存ルールと組み合わさるか
- 難しさが手順量だけで増えていないか
- 解けた瞬間に納得感があるか

## RPG

- 数値成長だけでなく選択肢が増えるか
- 装備更新が単純な上位互換だけになっていないか
- 戦闘前の準備が戦闘中の判断とつながるか
- 敵ごとに行動優先順位が変わるか
- 新技が旧技を完全に消していないか
- 探索・会話・戦闘のテンポに対比があるか

## Fighting

- キャラクターごとに間合いと勝ち筋が変わるか
- ガード後／ヒット後／空振り後の状況が読めるか
- 強い技にリスクがあるか
- 初心者でも意図した技を出せるか
- 上級者向けの入力精度や読み合いが残っているか
- 見た目の派手さがフレーム状況を隠していないか

## Horror

- 驚かせる回数より予測不能感を管理する
- 安全と危険の境界を完全には固定しない
- 情報不足と理不尽を区別する
- 音を単なる雰囲気ではなく情報として使う
- プレイヤー自身に危険を想像させる余白を作る
- 同じ脅かしを繰り返して学習されすぎないようにする

## Mobile / Touch

- 主操作を画面端へ追いやりすぎない
- 同時押し要求を必要最小限にする
- 指で重要情報を隠さない
- 視点操作とアクション操作を競合させない
- 長押し・スワイプ・タップの役割を一貫させる
- safe-areaを守る
- 誤タップ時の損失を大きくしすぎない
- 画面サイズに対してHUDを作りすぎない

## Score Attack

- 得点行動が通常攻略と少し違うリスクを要求するか
- 上級者ほど効率の良い連鎖を作れるか
- スコアの増加理由が分かるか
- リセット前提の極端な運要素を避ける
- 中間目標を可視化する


## Multiplayer / Co-op

- 人数が増えただけで、各プレイヤーの判断が変わっているか
- 協力・競争・妨害のどれを中心にするか明確か
- 自然な役割分担が発生するか
- 一人が全部解決して他の人が暇にならないか
- 他人の行動を見て自分の判断を変える必要があるか
- 負けた理由を相手の理不尽さではなく駆け引きとして理解できるか

## Arcade / Short Session

- 最初の数十秒でゲームの核に触れられるか
- 3〜5分でも一回の体験として満足感があるか
- 失敗時にもう一度やる改善案が見えるか
- 熟練者向けの深さが初心者の入口を塞いでいないか
- 高難度を選ぶ明確な魅力があるか
- プレイしている姿そのものが他人に伝わりやすいか


### RPG — progression and information

- レベルアップ前後で戦術が変わるか
- 全能力が一律上昇するだけになっていないか
- 強くなる方向をプレイヤーが選べるか
- 次の成長目標が理解できるか
- マップ・会話・弱点など、記憶する必要のない情報を適切に記録しているか
- 戦闘とマッピング／管理の切替が過度な作業になっていないか

## Adventure / Narrative

- 「難しい謎解き」が本当に中心体験か
- プレイヤーを物語の当事者にする操作があるか
- 正解を知ることより、世界を理解することが進行につながるか
- ヒントが段階的に強くなるか
- 重要情報が一度しか表示されず記憶頼みになっていないか
- 選択肢が物語上の反応を生み、単なるテキスト送りになっていないか
- 原作・外部知識を知っている人だけが極端に有利にならないか

## Knowledge / Discovery Games

- 初回プレイでも最低限遊べるか
- 知識が増えるほど効率や戦略が変わるか
- 知識が単なるパスワード暗記になっていないか
- 発見に弱い手掛かりがあるか
- 珍しい発見を記録／共有できるか
- 攻略情報を見なくても仮説を立てられるか


### Multiplayer / Co-op — entry and interdependence

- 招待からプレイ開始までが短いか
- 途中参加・途中離脱でセッション全体を壊さないか
- 人数増加を敵HP倍率だけで処理していないか
- 味方を観察することで自分の判断が変わるか
- 役割が固定職だけでなく状況から自然発生するか
- 一人の熟練者が他全員のゲームを奪わないか

## Strategy / Simulation AI

- CPUの判断を初期設計から考えているか
- AIが利用する情報範囲を定義しているか
- 同じ戦法へ毎回同じ反応をしないか
- 完全ランダムではなく候補行動の重み付けで変化させているか
- CPUだけの不可視情報が公平感を壊していないか
- 非対称なら勝利条件側で役割差を調整しているか
- Hardが反応速度・資源チートだけになっていないか
- プレイヤーがCPUを誘導・欺く余地があるか

## Sports

- 初心者が主要アクションを少数操作で実行できるか
- 詳細戦術は必要になるまで隠せるか
- Quick Playでも競技の面白さの核が残っているか
- Full/Advanced側で編成・戦術・マッチアップの深さが増えるか
- 操作選手の切替が自然か
- 実競技の複雑さを全部再現するのではなく判断の核を抽出しているか


### Fighting — matchup and state transition

- 技のダメージだけでなく終了位置・有利不利・次の選択を見る
- 強い戦法にゲーム内で学べる対抗策があるか
- キャラクター単体ではなく主要マッチアップを行列でテストする
- 投げ／打撃／防御が次の距離と主導権を変えるか
- 練習モードで対空・反撃・起き上がり等の状況を再現できるか
- 技入力の難しさが戦略理解を過度に塞いでいないか

### Racing — anticipation and rivals

- 高速時ほど先のコースが読めるか
- 急カーブ／障害に十分な予告距離があるか
- AI車が実際に走行ラインを変えさせるか
- タイムアタックと競争レースの面白さを区別しているか
- 振動／音／カメラからグリップや接触を読めるか
- 分岐ルートがリスク・景色・難度を変えるか
- ゴムバンド補正が不可視のズルに見えないか

### Shooter — recovery and power curve

- ミス後の最低装備でも復帰可能か
- 一回の死亡が連続死亡をほぼ確定させていないか
- チェックポイントごとに復帰用の敵・資源配置があるか
- パワーアップ選択がステージ形状や敵配置で変わるか
- ボム／緊急回避が「抱え落ち」だけを責める設計になっていないか
- 生存ルートと高得点ルートが少し分岐するか
- 敵出現間隔に緊張と呼吸があるか

### Puzzle — planning horizon

- 次状態をどこまで見せると計画が生まれるか
- 現在の一手が数手先へ影響するか
- 高速化だけでなく盤面形状や制約で難度を増やせるか
- プレイヤー自身が速度を上げて追加得点を狙えるか
- リセットが速く、仮説検証を妨げないか
- 追加ルールが元の判断を置き換えず拡張しているか

### RPG — economy and convenience

- 中盤以降も通貨に競合する使い道があるか
- 消耗品が「いつ使うか」の判断を作るか
- 上位装備が常に完全上位互換になっていないか
- 一度攻略済みの長距離移動を省く手段があるか
- 高頻度メニュー操作にショートカットがあるか
- セーブや宿泊などの費用が意味ある選択か、単なる税か
- お金が余ることでシステムが死んでいないか

### Arcade / Short Session — onboarding and retention

- デモが最高峰の技だけでなく「自分にもできそうな成功」を見せるか
- 練習モードで低速・限定状況を試せるか
- 一回の明確な終点が初心者に見えるか
- 完走後にエンドレス／スコア等の熟練層があるか
- 対象プレイヤーごとにセッション長と難易度を検証しているか
- 大会／ランキング等が同じコアへ新しい目標を与えられるか


### Horror — tension architecture

- 恐怖を敵出現回数だけで作っていないか
- 予告→不確実性→遭遇→解放→安全の周期があるか
- 音が敵の方向・距離・存在を推測させるか
- 安全地帯を裏切りすぎて休息を消していないか
- ゴアや大音量を連続使用して慣れさせていないか
- 固定カメラ／セーブ制限／操作摩擦が恐怖ではなく苛立ちを作っていないか

## Beat-em-up / Crowd Combat

- 敵数ではなく同時攻撃方向を管理しているか
- 背後敵を音・影・カメラで読めるか
- 長リーチ武器を持つプレイヤーに敵側も合理的な間合い手段があるか
- 大群が反応・吹き飛び・連鎖によって気持ちよく処理できるか
- 敵を倒す順番で空間が変わるか
- 画面を埋める敵数が視認性を超えていないか

## Save / Failure Systems

- 中断目的の保存と攻略上のセーブを分離しているか
- 失敗時に何分失うか測っているか
- 再実行部分に判断が残っているか
- セーブ地点が難所の後ろだけでなく前にも必要か
- オートセーブが取り返しのつかない状態を固定しないか
- 永続損失がゲームの中心体験と一致しているか

## Teaching / Tutorials

- 説明直後に安全に一度実行できるか
- 一度に覚えさせる操作が多すぎないか
- 高度機能は必要になった瞬間に開示されるか
- ヘルプをいつでも再確認できるか
- マニュアル相当の詳細情報と短い実戦教授を分離しているか
- チュートリアルをスキップした経験者が困らないか

## UGC / Editors

- 既存ステージ改変から始められるか
- 作成→試遊の往復が短いか
- テンプレートがあるか
- 高度設定を段階的に開けるか
- 他人の作品を簡単に試せるか
- 人気作品だけでなく新作が発見される導線があるか

## Community / Metagame

- 強い戦法に対策が存在するか
- リプレイや攻略共有が学習を助けるか
- 大会ルールがゲームの面白い部分を強調するか
- 想定外テクニックを一律で削除していないか
- tierや流行が固定しすぎる前に別の回答が生まれる余地があるか


## Rhythm / Music Games

- 判定時刻を描画フレームではなく音声時刻へ同期しているか
- 音／映像／入力オフセットを校正できるか
- Bluetooth等の環境差を想定しているか
- 判定が「早い／遅い」を学習できる形で返るか
- ミスしても曲の流れが完全に壊れないか
- 初心者譜面でも拍の構造が見えるか
- 上級譜面はノーツ量だけでなくリズム理解を要求するか
- 専用入力装置の反応性を実機で検証しているか

## Strategy UI / Information

- microとmacroを短い視線移動で往復できるか
- 頻繁に一緒に見る情報が画面端へ散っていないか
- 重要イベントが画面外で無通知に進行しないか
- 同じ命令を可視UIとホットキーの両方から実行できるか
- 高度情報を段階表示できるか
- 通知を緊急度で優先しているか
- 自動化が判断を奪わず反復操作だけを減らしているか

## Inventory / Loot UX

- アイテム数増加に検索・ソート・フィルターが追いついているか
- 売却候補を一括指定できるか
- 装備比較が同画面でできるか
- 同一アイテムを自動スタックできるか
- 小差の大量装備が判断より整理作業を増やしていないか
- 重要／お気に入り／クエスト品を誤処分しにくいか
- 持ち物制限が意思決定になっているか、往復作業になっているか

## 3D Camera

- 進行方向・敵・着地点のどれを今見せるべきか明確か
- 高速時に前方情報を多く見せるか
- 壁衝突後に対象が見えなくならないか
- 狭所・ボス・高速区間で専用カメラルールを設定できるか
- ロックオンが対象を画面内に維持できるか
- ターゲット切替が意図通りか
- カメラ操作をプレイヤーへ要求しすぎていないか

## Local Multiplayer

- 初回ルール説明が30秒以内に収まるか
- 負けたプレイヤーが長時間待たないか
- 再戦が速いか
- 観戦者も状況を理解しやすいか
- 同じ部屋だからこその会話・ブラフ・協力が生まれるか
- 能力差が大きい人同士でも一緒に遊べる調整があるか
- 共有画面のカメラ制約を協力ルールとして扱っているか

## Procedural Generation

- 生成結果の到達可能性を保証／検証しているか
- 最低品質のシードを探しているか
- シードで完全再現できるか
- 難易度曲線を乱数だけに任せていないか
- 形だけ変わって同じ判断になっていないか
- 手作りの部品・規則・ランドマークを使っているか
- 生成とプレイヤー能力を一緒に調整しているか
- 休息区間と山場を生成規則に含めているか


## Accessibility / Assist Design

- Easy/Hardだけでなく反応速度・精密入力・視認性などを個別調整できるか
- 重要情報を色だけ／音だけに依存していないか
- remap、hold/toggle、sensitivity等が必要か
- AssistをONにしても中心となる判断や学習が残るか
- presetと細かな設定を両方用意できるか
- game speed変更で物理・音・AIが壊れないか
- Assist設定を恥や罰として扱っていないか

## Rewards / Retention

- 報酬がコアゲームへ戻る理由になっているか
- ログインだけが最も効率的な行動になっていないか
- 固定報酬と変動報酬の役割を分けているか
- 遠い報酬までの進捗が見えるか
- 終盤プレイヤーにも報酬価値があるか
- 数日休んだプレイヤーを過度に罰していないか
- デイリー課題が自由な遊び方を狭めていないか

## Crafting

- レシピを一度に大量解禁していないか
- 素材→工程→完成の関係が理解しやすいか
- 素材種類が判断を増やしているか
- 用途不明素材が大量に溜まらないか
- 使用先を逆引きできるか
- よく使うレシピをお気に入り登録できるか
- 他プレイヤーの作業からクラフトを学べるか
- 素材収集が探索判断か単純周回か
