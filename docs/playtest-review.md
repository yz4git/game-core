# Playtest Review Framework

「画面を見てプレイチェックして改善する」ための共通レビュー手順。

## 0. 最初に見ること

プレイ開始後30秒以内に確認する。

- 何をすればよいか分かるか
- 操作対象が明確か
- 最重要ボタンが自然に見つかるか
- 初回入力に即座の反応があるか
- UIがゲーム画面を邪魔していないか
- タッチ／マウス／パッドで誤入力が起きないか

## 1. Core Feel

操作そのものを評価する。

- 入力遅延
- 加速／減速
- 旋回
- ジャンプ／回避／攻撃の出始め
- キャンセル可否
- ヒットストップ
- カメラ追従
- 被弾時の反応
- 効果音と視覚反応

**原則:** ここに重大な問題がある場合、新コンテンツ追加より先に直す。

## 2. Readability

戦闘中に情報が読めるか。

- 危険が背景に埋もれていないか
- 敵攻撃の予告が一貫しているか
- 自分の攻撃が当たったか分かるか
- 無敵／ガード／パリィ状態が分かるか
- 目的地と装飾が競合していないか
- エフェクト過多で敵モーションが見えなくならないか

## 3. Decision Density

10〜20秒単位で「意味のある選択」が何回あるかを見る。

意味のある選択とは、結果・リスク・位置・資源のどれかが変わる選択。

注意:
- ボタンを押しているだけ
- 一本道を走っているだけ
- 最強行動を連打しているだけ
- 敵が硬いだけ
は、入力が多くても判断密度は低い。

## 4. Dominant Strategy

最も簡単な行動を繰り返すだけで勝てないか確認する。

発見したら、単純な弱体化だけでなく、
- 敵配置
- 間合い
- クールダウン
- 安全策の機会損失
- 他行動との相互作用
で解決できないか検討する。

## 5. Learning Curve

ゲームが何を教え、いつ要求しているかを記録する。

各区間を次で分類:
- Introduce: 初めて見せる
- Practice: 安全に練習させる
- Test: 成功を要求する
- Combine: 別ルールと組み合わせる
- Mastery: 高精度を要求する

「初見なのにMastery」を要求していないかを確認する。

## 6. Enemy Role Audit

各敵について一行で答える。

> この敵が存在することで、プレイヤーの判断は何が変わる？

答えが「HPが高い」「色が違う」だけなら役割が弱い。

敵同士の組み合わせでも同じ確認を行う。

## 7. Reward Loop

行動 → 成功 → 報酬 → 次の行動、がつながっているか。

報酬は数値だけでなく、
- 主導権
- 新ルート
- 移動速度
- 視界
- コンボ継続
- 資源回復
- 情報
でもよい。

## 8. Failure Audit

死亡・失敗ごとに原因を分類する。

- 読み違い
- 入力ミス
- 情報不足
- カメラ
- UI
- 当たり判定
- 不可避
- ルール未理解
- リスク選択の結果

「不可避」「情報不足」「カメラ」が多い場合は難易度ではなく設計問題を疑う。

## 9. Pacing

プレイ動画を時系列で見て、
- 高密度
- 中密度
- 低密度
を記録する。

高密度が長く続きすぎても、低密度が長く続きすぎても単調になる。

## 10. Replay Value

クリア後に残る目標を確認する。

- より速い
- より高得点
- ノーダメージ
- 別ルート
- 別キャラ
- 別ビルド
- 隠し要素
- 高難度
- 自己ベスト

単なる周回要求ではなく、プレイ内容が変わる再挑戦理由を優先する。

## 11. Prediction Audit

プレイヤーが「見て反応する」だけでなく、次を予測できるかを見る。

- 敵の未来位置
- 攻撃が届く時刻
- ライバルのライン
- 弾道
- 次の危険地帯
- AIの巡回
- 数手後の盤面

予測が当たったときに、位置・時間・資源・主導権の利益があるかも確認する。

## 12. Feedback Cadence

大きな報酬まで何も返ってこない区間が長くないかを見る。

成功後に、
- 音
- ヒット反応
- 短い視覚変化
- 主導権変化
- 安全時間
- コンボ継続
などの小さな確認が返るか。

**目的:** 派手にすることではなく、「今の行動は正しかった」と学習できること。

## 13. Breath After Success

大きな成功の直後に、次の高密度区間へ即突入していないか。

ボス撃破、難所突破、連戦終了などの後には、
- 短い移動
- リザルト
- 景色の変化
- 安全地帯
- 報酬確認
のような低密度区間を検討する。

## 14. Retry Friction

高難度ほど「もう一度やるまでの時間」を計測する。

記録:
- 死亡 → 操作再開までの秒数
- 再挑戦前に必要な移動距離
- 再度見る必要がある演出
- 再度こなす簡単区間
- メニュー操作数

難易度と再挑戦コストは別に調整する。

## 改善優先順位

原則として次の順。

1. クラッシュ／進行不能
2. 入力・カメラ・当たり判定
3. 情報不足・視認性
4. 支配的戦法・ゲーム性崩壊
5. 難易度曲線
6. リトライ摩擦
7. テンポ
8. 報酬／フィードバック
9. コンテンツ追加
10. 装飾・高級感

見た目のクオリティアップは重要だが、1〜8を隠す目的では使わない。

## 1回のプレイチェックで残すメモ

- **Moment:** 何が起きたか
- **Feeling:** どう感じたか
- **Cause:** どの機構が原因か
- **Fix:** 最小の修正は何か
- **Expected:** 修正後どんな判断が増えるか
- **Regression Risk:** 他に何を壊す可能性があるか
- **Retry Cost:** 失敗から再挑戦まで何秒／何操作か
- **Prediction:** プレイヤーが次を読める材料があるか


## 15. Fairness Attribution

失敗した直後に、プレイヤーが原因を一文で説明できるか確認する。

理想:
- 欲張って攻撃した
- 回避が早すぎた
- 危険地帯へ入った
- 敵の予告を読み違えた

危険:
- なぜ当たったかわからない
- 当たり判定が見た目と違う
- 入力が無視されたように感じる
- 知らない即死条件だった

**目標:** 「理不尽ではない」だけでなく、「次の改善策が見える」こと。

## 16. Improvement Meter Audit

ゲームがプレイヤーの上達を何で測っているかを確認する。

候補:
- スコア
- タイム
- 被弾数
- コンボ
- ランク
- 到達地点
- 使用資源
- 勝率

その数値が本当に上手さと相関しているかを見る。

安全な稼ぎ・単純反復・知識だけの隠しボーナスが、技術より大きな値を生んでいないか確認する。

## 17. Spectator Readability

プレイしていない第三者が10秒見たときに、
- 操作対象
- 目的
- 危険
- 成功
- 失敗
- 優勢／劣勢
をおおよそ理解できるかを見る。

配信向けゲームだけでなく、ゲーム内の因果関係が整理されているかを見る簡易テストとして使える。


## 18. Forgiveness Audit

ゲームがプレイヤーの意図を必要以上に厳密に拒否していないかを見る。

確認:
- ボタンを少し早く押しただけで技が出ない
- 崖際で数フレーム遅れただけでジャンプ不能
- 見た目では当たっているのに攻撃が外れる
- タッチ位置が数pxずれただけで別操作になる
- アイテムの目前で取得できない

必要に応じて入力バッファ、コヨーテタイム、判定補正などを検討する。

**目的:** 自動で成功させることではなく、明確なプレイヤー意図を操作系が裏切らないこと。

## 19. Visual-in-Motion Audit

静止画ではなく実際のプレイ速度で録画を確認する。

- スクロール中も敵が背景から分離して見えるか
- エフェクト中も危険が読めるか
- カメラ移動でHUDとゲーム情報が競合しないか
- 高速移動時に進路が見えるか
- 小さい画面で重要情報が消えないか

スクリーンショットの美しさより、動的な可読性を優先する。

## 20. Fresh-Eyes Checkpoint

大きなマイルストーンごとに「既に知っていることを忘れたつもり」で最初から触る。

確認:
- チュートリアルなしで最初の目的が推測できるか
- 初見では知らない内部ルールを前提にしていないか
- 開発者だけが覚えているショートカットに依存していないか
- 慣れによって見逃していたUI摩擦がないか

可能なら初見プレイヤーの最初の5分を観察し、説明せずに詰まる場所を記録する。


## 21. Task-Switch Friction Audit

プレイヤーがゲーム中に別の操作モードへ何回切り替えるか数える。

例:
- 戦闘 → マップ
- 探索 → 外部メモ
- 移動 → 深いメニュー
- 会話 → ログ確認

各切替について、
> この手間自体が面白さの核か？

を確認する。

核でなければ、自動記録、クイック参照、統合UIなどで減らす。

## 22. Progression Decision Audit

成長前後のプレイを比較する。

記録:
- 使う技
- 安全距離
- リソース配分
- 敵の優先順位
- 装備選択
- ルート選択

数字だけ増えて行動が同じなら、成長システムの意味が薄い。

## 23. Enjoyment Test

バグ確認とは別に、一つのセッションを「楽しさ」だけで観察する。

記録:
- 初めて笑った／気持ちよかった瞬間
- 初めて退屈した瞬間
- 同じ行動を3回以上繰り返した場所
- 自分から試したくなった行動
- 説明されずに発見したこと
- もう一回やりたいと思った瞬間

修正優先度をクラッシュ数だけで決めない。

## 24. Discovery Gradient Audit

秘密・謎・攻略情報について、ヒントの強さを段階で確認する。

- Level 0: 完全ノーヒント
- Level 1: 存在の違和感
- Level 2: 探す場所の方向
- Level 3: 条件の絞り込み
- Level 4: ほぼ答え
- Level 5: 答えそのもの

重要な進行要素がLevel 0に留まっていないか、任意の秘密がLevel 5で最初から露出していないかを見る。
