# Playtest Review Framework

「画面を見てプレイチェックして改善する」ための共通レビュー手順。

## 0. 最初に見ること

プレイ開始後30秒以内に確認する。

- 何をすればよいか分かるか
- 操作対象が明確か
- 最重要ボタンが自然に見つかるか
- 初回入力に即座の反応があるか
- UIがゲーム画面を邪魔していないか
- タッチ／マウス／パッドで誤入力が起きないか

## 1. Core Feel

操作そのものを評価する。

- 入力遅延
- 加速／減速
- 旋回
- ジャンプ／回避／攻撃の出始め
- キャンセル可否
- ヒットストップ
- カメラ追従
- 被弾時の反応
- 効果音と視覚反応

**原則:** ここに重大な問題がある場合、新コンテンツ追加より先に直す。

## 2. Readability

戦闘中に情報が読めるか。

- 危険が背景に埋もれていないか
- 敵攻撃の予告が一貫しているか
- 自分の攻撃が当たったか分かるか
- 無敵／ガード／パリィ状態が分かるか
- 目的地と装飾が競合していないか
- エフェクト過多で敵モーションが見えなくならないか

## 3. Decision Density

10〜20秒単位で「意味のある選択」が何回あるかを見る。

意味のある選択とは、結果・リスク・位置・資源のどれかが変わる選択。

注意:
- ボタンを押しているだけ
- 一本道を走っているだけ
- 最強行動を連打しているだけ
- 敵が硬いだけ
は、入力が多くても判断密度は低い。

## 4. Dominant Strategy

最も簡単な行動を繰り返すだけで勝てないか確認する。

発見したら、単純な弱体化だけでなく、
- 敵配置
- 間合い
- クールダウン
- 安全策の機会損失
- 他行動との相互作用
で解決できないか検討する。

## 5. Learning Curve

ゲームが何を教え、いつ要求しているかを記録する。

各区間を次で分類:
- Introduce: 初めて見せる
- Practice: 安全に練習させる
- Test: 成功を要求する
- Combine: 別ルールと組み合わせる
- Mastery: 高精度を要求する

「初見なのにMastery」を要求していないかを確認する。

## 6. Enemy Role Audit

各敵について一行で答える。

> この敵が存在することで、プレイヤーの判断は何が変わる？

答えが「HPが高い」「色が違う」だけなら役割が弱い。

敵同士の組み合わせでも同じ確認を行う。

## 7. Reward Loop

行動 → 成功 → 報酬 → 次の行動、がつながっているか。

報酬は数値だけでなく、
- 主導権
- 新ルート
- 移動速度
- 視界
- コンボ継続
- 資源回復
- 情報
でもよい。

## 8. Failure Audit

死亡・失敗ごとに原因を分類する。

- 読み違い
- 入力ミス
- 情報不足
- カメラ
- UI
- 当たり判定
- 不可避
- ルール未理解
- リスク選択の結果

「不可避」「情報不足」「カメラ」が多い場合は難易度ではなく設計問題を疑う。

## 9. Pacing

プレイ動画を時系列で見て、
- 高密度
- 中密度
- 低密度
を記録する。

高密度が長く続きすぎても、低密度が長く続きすぎても単調になる。

## 10. Replay Value

クリア後に残る目標を確認する。

- より速い
- より高得点
- ノーダメージ
- 別ルート
- 別キャラ
- 別ビルド
- 隠し要素
- 高難度
- 自己ベスト

単なる周回要求ではなく、プレイ内容が変わる再挑戦理由を優先する。

## 11. Prediction Audit

プレイヤーが「見て反応する」だけでなく、次を予測できるかを見る。

- 敵の未来位置
- 攻撃が届く時刻
- ライバルのライン
- 弾道
- 次の危険地帯
- AIの巡回
- 数手後の盤面

予測が当たったときに、位置・時間・資源・主導権の利益があるかも確認する。

## 12. Feedback Cadence

大きな報酬まで何も返ってこない区間が長くないかを見る。

成功後に、
- 音
- ヒット反応
- 短い視覚変化
- 主導権変化
- 安全時間
- コンボ継続
などの小さな確認が返るか。

**目的:** 派手にすることではなく、「今の行動は正しかった」と学習できること。

## 13. Breath After Success

大きな成功の直後に、次の高密度区間へ即突入していないか。

ボス撃破、難所突破、連戦終了などの後には、
- 短い移動
- リザルト
- 景色の変化
- 安全地帯
- 報酬確認
のような低密度区間を検討する。

## 14. Retry Friction

高難度ほど「もう一度やるまでの時間」を計測する。

記録:
- 死亡 → 操作再開までの秒数
- 再挑戦前に必要な移動距離
- 再度見る必要がある演出
- 再度こなす簡単区間
- メニュー操作数

難易度と再挑戦コストは別に調整する。

## 改善優先順位

原則として次の順。

1. クラッシュ／進行不能
2. 入力・カメラ・当たり判定
3. 情報不足・視認性
4. 支配的戦法・ゲーム性崩壊
5. 難易度曲線
6. リトライ摩擦
7. テンポ
8. 報酬／フィードバック
9. コンテンツ追加
10. 装飾・高級感

見た目のクオリティアップは重要だが、1〜8を隠す目的では使わない。

## 1回のプレイチェックで残すメモ

- **Moment:** 何が起きたか
- **Feeling:** どう感じたか
- **Cause:** どの機構が原因か
- **Fix:** 最小の修正は何か
- **Expected:** 修正後どんな判断が増えるか
- **Regression Risk:** 他に何を壊す可能性があるか
- **Retry Cost:** 失敗から再挑戦まで何秒／何操作か
- **Prediction:** プレイヤーが次を読める材料があるか


## 15. Fairness Attribution

失敗した直後に、プレイヤーが原因を一文で説明できるか確認する。

理想:
- 欲張って攻撃した
- 回避が早すぎた
- 危険地帯へ入った
- 敵の予告を読み違えた

危険:
- なぜ当たったかわからない
- 当たり判定が見た目と違う
- 入力が無視されたように感じる
- 知らない即死条件だった

**目標:** 「理不尽ではない」だけでなく、「次の改善策が見える」こと。

## 16. Improvement Meter Audit

ゲームがプレイヤーの上達を何で測っているかを確認する。

候補:
- スコア
- タイム
- 被弾数
- コンボ
- ランク
- 到達地点
- 使用資源
- 勝率

その数値が本当に上手さと相関しているかを見る。

安全な稼ぎ・単純反復・知識だけの隠しボーナスが、技術より大きな値を生んでいないか確認する。

## 17. Spectator Readability

プレイしていない第三者が10秒見たときに、
- 操作対象
- 目的
- 危険
- 成功
- 失敗
- 優勢／劣勢
をおおよそ理解できるかを見る。

配信向けゲームだけでなく、ゲーム内の因果関係が整理されているかを見る簡易テストとして使える。


## 18. Forgiveness Audit

ゲームがプレイヤーの意図を必要以上に厳密に拒否していないかを見る。

確認:
- ボタンを少し早く押しただけで技が出ない
- 崖際で数フレーム遅れただけでジャンプ不能
- 見た目では当たっているのに攻撃が外れる
- タッチ位置が数pxずれただけで別操作になる
- アイテムの目前で取得できない

必要に応じて入力バッファ、コヨーテタイム、判定補正などを検討する。

**目的:** 自動で成功させることではなく、明確なプレイヤー意図を操作系が裏切らないこと。

## 19. Visual-in-Motion Audit

静止画ではなく実際のプレイ速度で録画を確認する。

- スクロール中も敵が背景から分離して見えるか
- エフェクト中も危険が読めるか
- カメラ移動でHUDとゲーム情報が競合しないか
- 高速移動時に進路が見えるか
- 小さい画面で重要情報が消えないか

スクリーンショットの美しさより、動的な可読性を優先する。

## 20. Fresh-Eyes Checkpoint

大きなマイルストーンごとに「既に知っていることを忘れたつもり」で最初から触る。

確認:
- チュートリアルなしで最初の目的が推測できるか
- 初見では知らない内部ルールを前提にしていないか
- 開発者だけが覚えているショートカットに依存していないか
- 慣れによって見逃していたUI摩擦がないか

可能なら初見プレイヤーの最初の5分を観察し、説明せずに詰まる場所を記録する。


## 21. Task-Switch Friction Audit

プレイヤーがゲーム中に別の操作モードへ何回切り替えるか数える。

例:
- 戦闘 → マップ
- 探索 → 外部メモ
- 移動 → 深いメニュー
- 会話 → ログ確認

各切替について、
> この手間自体が面白さの核か？

を確認する。

核でなければ、自動記録、クイック参照、統合UIなどで減らす。

## 22. Progression Decision Audit

成長前後のプレイを比較する。

記録:
- 使う技
- 安全距離
- リソース配分
- 敵の優先順位
- 装備選択
- ルート選択

数字だけ増えて行動が同じなら、成長システムの意味が薄い。

## 23. Enjoyment Test

バグ確認とは別に、一つのセッションを「楽しさ」だけで観察する。

記録:
- 初めて笑った／気持ちよかった瞬間
- 初めて退屈した瞬間
- 同じ行動を3回以上繰り返した場所
- 自分から試したくなった行動
- 説明されずに発見したこと
- もう一回やりたいと思った瞬間

修正優先度をクラッシュ数だけで決めない。

## 24. Discovery Gradient Audit

秘密・謎・攻略情報について、ヒントの強さを段階で確認する。

- Level 0: 完全ノーヒント
- Level 1: 存在の違和感
- Level 2: 探す場所の方向
- Level 3: 条件の絞り込み
- Level 4: ほぼ答え
- Level 5: 答えそのもの

重要な進行要素がLevel 0に留まっていないか、任意の秘密がLevel 5で最初から露出していないかを見る。


## 25. AI Fairness Audit

CPU対戦・敵AIで、負けた直後に次を確認する。

- CPUが自分には見えない情報を使ったように感じたか
- 人間では不可能な反応速度に見えたか
- 同じ誘導で永久にハメられないか
- AIの反応理由を観察から推測できるか
- 難易度上昇が「ズルの増加」になっていないか

勝率だけでなく公平感を記録する。

## 26. Depth-Layer Audit

初回30秒、10分、1時間で見えている複雑さを分けて確認する。

- 初回から不要な詳細設定を見せていないか
- 最初の成功までに覚える用語が多すぎないか
- 中盤から新しい判断が増えるか
- 上級者に最適化余地が残っているか

初心者向けにシステムを削りすぎず、必要になるまで隠す方法を優先する。

## 27. Co-op Join Friction

協力プレイを開始するまでの時間と操作数を測る。

記録:
- 招待から操作開始まで
- 途中参加の可否
- 途中離脱時の影響
- 復帰までの手順
- 装備／キャラ選択の待ち時間

「一緒に遊ぶこと」がコアなら、合流手続きで熱量を失わないようにする。

## 28. Co-op Interdependence Audit

2人以上で遊んだとき、自分以外のプレイヤーを見る必要があるか確認する。

良い兆候:
- 味方の位置で進路を変える
- 味方の攻撃に合わせる
- 味方の資源不足を補う
- 役割を自然に分担する
- 味方のミスを救える

弱い兆候:
- 敵HPだけ増える
- 各自が別々に殴るだけ
- 一人が全部解決できる


## 29. Recovery-State Audit

死亡後を通常プレイとは別にテストする。

同じチェックポイントを、
- 強い装備
- 平均装備
- 最低装備
で開始し、突破可能性とストレスを比較する。

「上手く立て直せる」余地があるか確認する。

## 30. Beginner Demonstration Audit

初見プレイヤーにデモ／Attract／チュートリアルを見せる。

確認:
- 自分にもできそうと思うか
- 何を操作しているか分かるか
- 最初の成功が理解できるか
- 熟練プレイが速すぎて萎縮しないか

## 31. Counterplay Audit

強い行動を一つ選び、対抗手段を列挙する。

各対抗手段について、
- ゲーム内で存在を学べるか
- 実行難度が妥当か
- 成功時に状況が変わるか
を確認する。

## 32. Matchup Matrix Audit

対戦キャラクター／武器／デッキの主要組み合わせを行列で見る。

各組み合わせで、
- 得意距離
- 主導権
- 安全行動
- 反撃
- 資源差
を記録する。

単体テストだけでバランスを判断しない。

## 33. Scenario Training Audit

練習モードで、技一覧だけでなく実戦状況を再現できるか確認する。

最低候補:
- 対空
- 反撃
- 復帰
- 画面端
- 特定敵攻撃
- 特定距離

失敗した場面へ短時間で戻れることを重視する。

## 34. High-Speed Preview Audit

高速移動中に「危険認知 → 判断 → 入力 → 車体反応」までの時間を測る。

速度が上がるほど、視界・カメラ先読み・標識などで必要な予告距離を確保する。

## 35. Rival-Interaction Audit

レースのAI車を消した状態と入れた状態を比較する。

AI車がいることで、
- ライン
- ブレーキ
- リスク
- 追い越し場所
が変わらないなら、ライバルの役割が弱い。

## 36. Future-State Information Audit

ゲームが未来情報をどれだけ見せているか確認する。

- 完全非公開
- 直近1手
- 複数手
- 確率
- 意図だけ

情報量を変えて、反応ゲームと計画ゲームの比率を調整する。

## 37. Economy Sink Audit

ゲーム中盤・終盤で、通貨を「惜しい」と感じながら使う場面があるか確認する。

記録:
- 所持金
- 欲しい購入物
- 実際の支出
- 余剰額

一つの最適購入だけ、または使い道が消える状態を探す。

## 38. High-Frequency UI Audit

各UI操作について、
**1回の手数 × 想定総回数**
で負担を見る。

使用頻度が高いものから、
- ショートカット
- 直接操作
- 前回選択維持
を検討する。

## 39. Causal Feedback Audit

シミュレーション／育成で設定を変更した後、
プレイヤーが「何が変わったか」を理解するまでの時間を測る。

原因と結果が遠すぎる場合は、中間フィードバックを追加する。

## 40. Audience-Segment Audit

初心者／経験者／短時間プレイヤーなどを分けて、
- 初成功時間
- セッション長
- 離脱点
- 再挑戦率
を比較する。

全員の平均値だけで難易度を決めない。


## 41. Audio-Only Information Audit

画面を見ない状態で、次をどこまで判断できるか確認する。

- 危険接近
- 方向
- 残り時間
- 成功／失敗
- リロード／準備完了
- 状態異常

重要音がBGMや連続SEに埋もれていないかも確認する。

## 42. Horror Tension Audit

恐怖区間を、
- 予告
- 不確実性
- 接近
- 遭遇
- 解放
- 安全
に分解する。

遭遇だけを連続させず、予告と安全の時間が機能しているかを見る。

## 43. Save-Loss Audit

各セーブ地点について死亡時に失うものを記録する。

- 分
- 戦闘
- 移動
- 会話
- アイテム整理
- パズル操作

再実行部分に新しい判断がない場合、保存間隔を短くする候補。

## 44. Suspend-vs-Challenge Audit

ゲーム内の中断保存と、攻略上のセーブ制限を分離できているか確認する。

「今日はここでやめたい」だけのプレイヤーに、攻略上の罰を与えていないかを見る。

## 45. Teaching Transfer Audit

説明された操作を、実際のゲームで何秒後に使わせるか測る。

説明から実行まで長すぎる場合、忘却する。

安全な実行 → 軽い応用 → 実戦、の順になっているか確認する。

## 46. Threat-Direction Audit

戦闘遭遇ごとに、同時に注意する方向を数える。

- 前
- 後
- 左右
- 上下
- 遠距離
- 画面外

敵数が同じでも方向数が急増していないか確認する。

## 47. Offscreen Threat Audit

画面外から被弾したケースを記録する。

被弾前に、
- 音
- 方向表示
- 影
- カメラ余白
- 侵入予告
のどれが存在したか確認する。

## 48. UGC Creation Loop Audit

エディタがある場合、
作る → 試す → 修正 → 共有
の一周に必要な時間と手数を測る。

作品制作よりツール操作の学習が支配的になっていないかを見る。

## 49. Metagame Health Audit

コミュニティで強い戦法が見つかったと仮定して、
- 対策があるか
- 対策の対策があるか
- 一つの回答でゲーム全体が終わらないか
を見る。

## 50. Exploit Classification

想定外挙動を見つけたら、即修正せず分類する。

- Progress blocker
- Dominant strategy
- Competitive unfairness
- Skillful technique
- Cosmetic oddity
- Fun emergent behavior

上3つを優先修正し、下3つはゲーム性への影響を見て判断する。


## 51. Rhythm Calibration Audit

同じ譜面を、
- 本体スピーカー
- 有線
- Bluetooth
- 異なる表示環境
で試す。

入力／音／映像のオフセット差を記録し、校正で吸収できるか確認する。

## 52. Timing Feedback Audit

ミス判定について、
- 早い
- 遅い
- 大きく外れた
をプレイヤーが理解できるか確認する。

単なるBad表示で学習が止まっていないかを見る。

## 53. Music-Flow Audit

失敗が頻発したとき、
- 曲が途切れる
- テンポ感が消える
- 判定基準を聞き取れない
状態になっていないか確認する。

## 54. Strategy Attention Audit

プレイ中の視線移動を観察し、
- 戦場
- 資源
- 生産
- ミニマップ
- 命令
の間を何回移動するか記録する。

頻繁にセットで使う情報が離れすぎていないか確認する。

## 55. Notification Priority Audit

通知を
- 即時対応
- 近いうち
- 記録のみ
に分類する。

低優先通知が高優先通知を押し流していないかを見る。

## 56. Inventory Search Audit

100件以上の持ち物を仮定し、
- 特定アイテムを探す
- 比較する
- 売る
- 装備する
までの時間と操作数を測る。

## 57. Obvious-Work Audit

プレイヤーが毎回同じ正解操作をしているUI作業を記録する。

自動化しても判断が失われないなら削減候補。

## 58. Camera Information Audit

カメラが映しているものを、
- 操作対象
- 目的地
- 敵
- 着地点
- 危険
で分類する。

キャラは見えるが次の判断材料が見えない場面を探す。

## 59. Camera Occlusion Audit

壁・柱・大型敵・味方で操作対象や敵が隠れる場面を収集する。

カメラ衝突回避が視認性を悪化させていないか確認する。

## 60. Shared-Screen Social Audit

ローカルマルチで、
- 声を掛ける
- 笑う
- 騙す
- 応援する
- 交代する
など、画面外の行動が自然に起きるか観察する。

## 61. Procedural Quality-Floor Audit

大量のシードを自動／手動評価し、
- 不可能
- 極端に簡単
- 極端に難しい
- 同じに感じる
- 報酬不足
の最低ケースを探す。

平均的に面白いことより、壊れたシードを減らすことを先に見る。

## 62. Seed Reproduction Audit

発見した生成不具合を、シードだけで完全再現できるか確認する。

修正後に同じシードとランダムな別シード群の両方を再テストする。


## 63. Accessibility-Dimension Audit

失敗原因を、
- reaction
- precision
- repetition
- vision
- hearing
- memory
- strategy
に分類する。

難易度を下げる際、どの負荷を変えるべきか特定する。

## 64. Redundant-Cue Audit

重要イベントについて、
- 色
- 形
- 音
- テキスト
- 振動
の何種類で伝えているか確認する。

一つの感覚だけに依存していないかを見る。

## 65. Assist-Core Audit

各Assist設定をONにした状態で、
> このゲームで本来学んでほしい判断はまだ残っているか
を確認する。

補助が中心技能まで自動化していないかを見る。

## 66. Reward-Motivation Audit

プレイ後に、
- 面白いから続けた
- 報酬が欲しくて続けた
- 途切れるのが怖くて続けた
を区別して記録する。

外的報酬がコア動機を置き換えていないか確認する。

## 67. Daily-Pressure Audit

数日休んだ場合に何を失うか一覧化する。

損失が大きすぎて復帰意欲を下げないか確認する。

## 68. Long-Term Progress Audit

遠い報酬へ向かう過程で、
- 現在進捗
- 次の小目標
- 何をすれば進むか
が見えるか確認する。

## 69. Crafting-Overload Audit

新しい設備／章を解禁した瞬間に増えるレシピ数を数える。

一度に大量表示され、何から試すべきか分からなくなっていないかを見る。

## 70. Material-Clutter Audit

各素材について、
- 使い道数
- 使用頻度
- 売却価値
- 将来用途表示
を確認する。

用途不明素材がインベントリを占有していないかを見る。


## 71. Road-Graph Audit

生成都市で、
- 主要地点間の到達経路数
- dead end率
- 幹線への接続
- 交差点間隔
を計測する。

単に接続しているだけでなく都市としての道路階層が見えるか確認する。

## 72. Driveability Agent Audit

自動車AIで多数seedを走らせ、
- 平均速度
- 急ブレーキ
- スタック
- Uターン
- 路外逸脱
を記録する。

到達率100%でも運転品質が悪いseedを弾く。

## 73. Landmark Recall Audit

一度走った地区について、プレイヤーが
> どこを走っていたか
をランドマーク・色・道路形状から説明できるか確認する。

## 74. LOD Navigation Audit

遠・中・近距離LODごとに、
- 道路
- 分岐
- ランドマーク
- 走行境界
が判断可能か確認する。

LOD切替で道が消える／位置が変わるseedを探す。

## 75. Replay Determinism Audit

同一入力／seedのリプレイを複数回再生し、
- 終了状態
- 主要イベント時刻
- スコア
が一致するか確認する。

演出差とゲーム結果差を分けて扱う。

## 76. Replay Version Audit

旧バージョンのreplay / ghostを新バージョンで再生した場合、
- compatibility
- warning
- archival playback
のどれを行うか明確にする。

## 77. Kill-Cause Audit

死亡リプレイを見た後、プレイヤーが一文で
> なぜ死んだか
を説明できるか確認する。

## 78. Spectator Drop-In Audit

ゲームを知らない人が途中から30秒見て、
- objective
- leader
- danger
- current conflict
を説明できるか確認する。

## 79. Highlight Meaning Audit

自動ハイライトが選んだ場面について、
> なぜ重要だったか
をゲーム状態から説明できるか確認する。

派手な演出だけを拾っていないかを見る。

## 80. Touch Eyes-on-Action Audit

タッチ操作中、プレイヤーが指位置を確認するためにHUDへ視線を落としていないか観察する。

視線が操作部へ頻繁に落ちるなら領域を広げる／動的化する。

## 81. Finger-Occlusion Audit

重要対象の上に指が重なる時間を測る。

操作中に敵・道路・着地点が隠れていないか確認する。

## 82. Grip-Posture Audit

片手／両手、縦／横で主要操作へ無理なく届くか確認する。

端末サイズ差も含める。

## 83. Touch-Decision Preservation Audit

コンソール版等から移植した場合、
- 削除した入力
- 統合した入力
ごとに「失われた判断」がないか確認する。

## 84. UGC Cold-Start Audit

新規投稿を人気0の状態から公開し、
- discovery surface
- first playまでの時間
- exposure回数
を記録する。

人気順だけで永久に埋もれないか確認する。

## 85. UGC Moderation Audit

投稿・共有可能な各フィールドについて、
- report可能か
- block可能か
- 年齢制限対応
- review手段
を確認する。

## 86. Creator Feedback Audit

UGC作者が、
- play count
- completion
- quit point
- rating
を見て次作へ反映できるか確認する。

## 87. Return-After-Break Audit

1週間／1か月休んだ想定で復帰し、
- 現在目標理解
- 操作再学習
- 装備／build理解
- catch-up
に何分必要か測る。

## 88. Absence-Penalty Audit

休止中に失うものを一覧化する。

失う量が大きすぎて「戻るのが怖い」状態になっていないか確認する。


## 89. Replay Divergence Audit

同一runを再生し、一定間隔のstate hashを比較する。

最初に不一致になったframe/tickを記録し、その前後のRNG・physics・input順序を調べる。

## 90. Replay Storage Audit

1分／10分／1時間のreplayサイズを測る。

- raw snapshot
- delta
- input log
の比率を確認し、用途に対して過剰保存していないかを見る。

## 91. Safe-Area Input Audit

iPhoneの複数機種・向きで、
- Home indicator
- Dynamic Island
- rounded corner
- system gesture
と主要入力が競合しないか確認する。

## 92. Simultaneous-Touch Audit

ゲーム中に必要な同時入力を列挙し、
左右どちらの親指が担当するか図にする。

一つの指へ矛盾する要求が集中していないかを見る。

## 93. Haptic Semantics Audit

各振動について、
> 何を意味するか
を一文で定義する。

複数の別イベントが同じpatternで区別不能になっていないか確認する。

## 94. Moderation Evidence Audit

UGC report一件から、
- 対象
- 理由
- 証拠
- 時刻
- 発生画面
をmoderatorが再構築できるか確認する。

## 95. UGC Version Audit

公開UGCを編集後、
- old replay
- old leaderboard
- old moderation report
- old rating
がどのversionを指すか追跡できるか確認する。

## 96. Remix Attribution Audit

remix作品からoriginalまで系譜を辿れるか確認する。

作者名だけでなく、どのversionを元にしたか残す。

## 97. Returning-MMR Audit

長期休止ユーザーの最初の10戦で、
- opponent strength
- rating change
- confidence
- win/loss
を追跡する。

過去ratingへ固執しすぎず、数戦で適応できるか確認する。

## 98. Return Warm-up Audit

1か月休止想定のプレイヤーがranked前に、
- controls
- meta changes
- current build
を思い出す安全な導線があるか確認する。

## 99. Canonical-Seed Regression Audit

過去bug seed、極端seed、代表seedを固定セット化し、generator変更ごとに自動実行する。

## 100. Procedural Tail-Risk Audit

多数seedの平均だけでなく、
- worst 1%
- failure count
- p95
を比較し、少数の破綻が隠れていないかを見る。


## 101. Headless Seed Farm Audit

CI/夜間ジョブで大量seedを生成し、
- hard fail count
- p95/p99 metrics
- worst-N
を保存する。

失敗seedはcanonical setへ追加する。

## 102. Failure Artifact Audit

自動テスト失敗時に、
- seed
- version
- screenshot
- metrics
- trace
が一つのartifactとして残るか確認する。

## 103. Replay First-Divergence Audit

同一runのstate hashをtick単位で比較し、
最初の不一致tickを自動表示できるか確認する。

## 104. Authoritative-State Audit

Replay hashへ、
- gameplay state
と
- cosmetic state
を混在させていないか確認する。

見た目差だけで競技replayをfailさせない。

## 105. Side-Effect Replay Audit

rewind / rollback / replayで、
- SE二重再生
- haptic二重発火
- analytics重複
- achievement重複
が起きないか確認する。

## 106. Long-Session Touch Audit

30分／60分プレイ後に、
- thumb pain
- grip change
- reach miss
- accidental system gesture
を記録する。

## 107. UGC Ranking Abuse Audit

同一作品へ短時間に大量評価を送るscenarioを作り、
順位が異常に変化しないか確認する。

## 108. UGC Appeal Audit

誤moderation想定で、
creatorが
- reason
- affected content/version
- appeal
へ到達できるか確認する。

## 109. Restricted-UGC Graceful Audit

UGC制限ユーザーで、
- restricted contentだけ見えない
- core gameは可能な限り遊べる
- 理由が説明される
ことを確認する。

## 110. Returner Opponent-Fairness Audit

復帰者の最初の10戦について、
本人だけでなく対戦相手側の
- expected win probability
- stomp rate
- rematch/quit
も確認する。


## Short-session economy / public-play review — Batch 16

- Continue使用後も次の失敗を避けたい緊張が残るか
- Continue/buy-inがskill rankやmastery signalを金・回数だけで代替していないか
- scoreが報酬へ変換される場合、reward/minute最大行動が意図した遊びと一致するか
- 意図的な死亡、restart、safe loop、time extensionで報酬をfarmできないか
- 初見の観戦者が10〜20秒で「何をすればよいか」を説明できるか

- 運営設定を変更したときonboarding、fairness、reward economyが壊れないか
