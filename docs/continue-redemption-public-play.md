# Continue, Redemption, and Public-Play Economics

## Purpose

Short-session and public-play games are not only combat or control systems. Failure recovery, session length, score, persistent rewards and spectators jointly change player behavior.

## 1. Separate continuation from mastery

A continue/revive may preserve momentum without preserving every achievement signal.

Useful separation:
- **completion state** — where the run resumes
- **mastery state** — score, rank, streak, no-continue badge
- **economy state** — tokens/currency/reward eligibility

This allows accessibility and persistence without making the skill metric meaningless.

## 2. Treat score-to-reward conversion as an economy

Once score buys or unlocks something, test:
- reward per minute
- reward per risk
- deliberate death/restart
- safe repetitive loops
- time-extension loops
- continue abuse

The highest-yield strategy should not contradict the intended core play.

## 3. Different objectives can require different modes

Score attack, ranked competition, progression farming and casual completion need not share every parameter.

Change rules only when the objective truly differs; avoid needless mode fragmentation.

## 4. Operational settings are design parameters

Bound and test:
- difficulty
- session timer
- continue count
- checkpoint distance
- reward multiplier
- demo/attract duration
- input calibration

Provide validated presets. A setting that operators/event staff can change is effectively live game design.

## 5. Public onboarding is a funnel

Design the sequence:

**notice → watch → understand → imagine success → start → first success → retry**

The attract/demo state should show:
- immediate goal
- player-controlled object
- one understandable threat
- one achievable success
- how to start

Do not fill it only with expert spectacle.

## 6. Linked play must create changed decisions

Adding seats is not enough. Other players should alter:
- target priority
- route choice
- timing
- resource allocation
- positioning
- risk

If replacing humans with non-interactive ghosts barely changes play, the social mechanism is weak.

## 7. Results should generate the next conversation

For cooperative/team public play, surface diverse contribution:
- assists
- saves
- setup
- pressure
- recovery
- objective work

Avoid reducing every player to one kill/score column when the game expects complementary roles.

## 8. Measure throughput with satisfaction

For short public sessions, monitor together:
- starts/hour
- median session duration
- completion rate
- immediate replay rate
- continue acceptance
- queue abandonment where applicable

A faster turnover is not automatically a better design if replay desire collapses.

## 9. Reusable platform, distinct decision loop

Reusable input, save, PWA, replay and telemetry infrastructure is valuable. Reuse should not turn new games into reskins.

Ask: **what decision does this game create that the shared shell does not?**

## Playtest checklist

- Does continue remove tension?
- Can buy-in substitute for mastery?
- Does reward farming resemble intended play?
- Can spectators identify the goal quickly?
- Does another human change decisions?
- Does the result screen encourage a rematch?
- Are operator/event presets safe?
- Are session length and replay desire both healthy?
