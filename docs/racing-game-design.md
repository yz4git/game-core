# Racing Game Design

レースを「速度」だけでなく、予測・ライン・ライバル・車体情報・ルートで設計する。

## 1. Speed needs preview

高速になるほど判断時間が減る。

必要な情報:
- カーブ方向
- 勾配
- 障害
- ライバル位置
- 分岐
を速度に応じて早く見せる。

「見えないから難しい」と「速い状況を予測するから難しい」は別。

## 2. Racing line

少なくとも次のライン差を作る。

- 最速
- 安全
- 追い越し
- 防御
- 回復／資源
- 破壊／攻撃

一つの理想線をなぞるだけより、状況で線を変えるほうが判断が生まれる。

## 3. Rivals as moving constraints

AI車は順位表ではなく地形の一部として作用させる。

- インを塞ぐ
- 外へ押し出す
- ブレーキ地点を変える
- スリップストリームを作る
- 接触リスクを作る

タイムアタックとは異なる判断を明確にする。

## 4. Vehicle feedback

画面・音・振動から状態を読めるようにする。

- タイヤ限界
- 路面変化
- 接触
- エンジン負荷
- 空中／着地
- ターボ

数値メーターだけでなく身体感覚へ変換する。

## 5. Branching routes

分岐は操作を増やさず再挑戦理由を作る。

分岐ごとの差:
- 難度
- 時間
- 景観
- ライバル密度
- 報酬
- 路面

走行後にルート履歴を見せると未体験部分が分かる。

## 6. Rubber band fairness

追いつき補正を使う場合、不可視の瞬間移動のように感じさせない。

代替:
- 後方車への資源
- 先頭の高リスクライン
- ミス後の復帰加速
- 自然なドラフティング

「上手く走ったのに無意味」と感じさせない。

## 7. Memory and mastery

コース記憶は悪ではない。

良い記憶:
- 次のカーブを予測して速度を作る
- 近道条件を覚える
- 地形変化に合わせてラインを選ぶ

悪い記憶:
- 初見では避けられない即死障害
- 視界外から突然出る障害

## 8. Playtest questions

- 最高速で初見反応可能な予告距離があるか
- ライバルがいることでラインが変わるか
- ブレーキが失敗修正以外の戦略になるか
- 振動／音だけでグリップ限界をある程度読めるか
- 分岐を変えると走り方も変わるか
