# Arcade Session & Attract Design

アーケード運営資料から抽象化した、短時間プレイ・初心者導入・観戦・再挑戦の設計。

家庭用・スマホでも「短いセッション」の設計に転用できる。

## 1. Session target

難易度は抽象的なEasy/Hardだけでなく、
- 数回遊んだ初心者が何分続くか
- 一つの達成まで何分か
を目標として調整する。

短すぎれば理解前に終わり、長すぎれば一回の区切りがぼやける。

## 2. Learn-the-game mode

説明文だけでは足りない場合、
- 低速
- 少ない敵
- 明確な一課題
- 即再試行
を使う。

「知識を読む」から「安全に試す」へ変える。

## 3. Attract mode

デモの目的は豪華さだけではない。

見せる:
- 操作対象
- 入力と結果
- 一つの成功
- ゲームの目標

最高難度の超絶プレイだけを見せると、初心者が「自分には無理」と感じることがある。

## 4. Continue and continuity

失敗後に前の進行へ戻れる仕組みは、
- 未見コンテンツを見る
- 学習を継続する
- セッションを切らない
役割を持つ。

ただしスコアアタックなど、ノーコンティニューに意味がある目標とは分離する。

## 5. Clear end vs endless

初心者には完走できる終点を提示し、
熟練者には
- 周回
- スコア
- エンドレス
- 高難度
を追加する。

## 6. Audience segmentation

プレイヤー層ごとに観察する。

- 初心者
- 熟練者
- 短時間利用
- 長時間利用

平均だけを見ると、誰にも合わない調整になる。

## 7. Community layer

大会・ランキング・期間課題は、同じゲームに新しい目的を作る。

必要:
- 明確な共通ルール
- 記録の可視化
- 比較対象
- 達成期限

## 8. Real behavior over hype

新技術や見栄えより、
- 実際に何人が遊ぶか
- 何回再挑戦するか
- 何分続くか
を見る。

短期の第一印象と長期の定着を分けて評価する。

## 9. Playtest questions

- デモを見ただけで基本目的が分かるか
- 熟練プレイが初心者を萎縮させないか
- 最初の成功まで何秒か
- 数回目の平均セッション長はどれくらいか
- 明確な終点と、その後の熟練目標が両方あるか
