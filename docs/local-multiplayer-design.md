# Local Multiplayer Design

同じ場所にいること自体をゲーム資源として使う。

## 1. Design for the room

ローカルマルチでは、画面以外に
- 会話
- 笑い
- ブラフ
- 身振り
- 応援
がある。

オンラインの模倣ではなく、同室だから可能な相互作用を使う。

## 2. Fast comprehension

パーティ環境では説明時間を短くする。

理想:
- 目的が一文
- 主操作が数個
- 1ラウンドで学べる

深さはプレイ後に発見させる。

## 3. Rapid rounds

負けた人を長く待たせない。

- 短いラウンド
- 即再戦
- 敗者復帰
- 観戦しても楽しい

を検討する。

## 4. Spectator value

同室では待っている人も観客になる。

遠目でも、
- 誰が勝っている
- 何が起きた
- 逆転した
が分かる画面にする。

## 5. Shared screen

共有画面では全員をフレーム内に保つ必要がある。

離れすぎ制限は、
- 強制集合
- 助け合い
- 引っ張り合い
というルールにできる。

## 6. Split screen

分割画面では各プレイヤーの情報量を確保できるが、
- 画面が小さい
- お互いを見にくい
- 処理負荷
が増える。

ゲームの中心が独立移動か共同空間かで選ぶ。

## 7. Skill gaps

家族・友人では技能差が大きい。

補助:
- 簡単操作
- ハンデ
- チーム制
- 追いつき機構

を使えるが、上手い人の技能を完全に無効化しない。

## 8. Physical interaction

タッチ／モーションでは、同じ端末上で押し合うこと自体を遊びにできる。

ただし端末を落とす・手をぶつける危険は避ける。

## Playtest

- 30秒で全員遊び始められるか
- 敗者が何秒待つか
- 画面を見ていない人も笑う瞬間があるか
- 技能差のある2人が同時に楽しめるか
- 同室である意味がゲームにあるか
