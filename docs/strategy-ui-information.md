# Strategy UI & Information

RTS／TBS／シミュレーションで、大量情報を「見つける作業」ではなく「判断」へ変える。

## 1. Three scales

情報を3層に分ける。

### Micro
単一ユニット・戦闘。

### Local / Wide
一つの戦線・画面範囲。

### Macro
全マップ、資源、生産、研究。

プレイヤーが層を短時間で往復できるUIにする。

## 2. Attention hubs

頻繁に一緒に見る情報を、画面の複数端へ散らさない。

1〜2個の主要視線拠点へまとめる。

## 3. Visual UI + shortcuts

初心者:
- アイコン
- ボタン
- ツールチップ

熟練者:
- ホットキー
- グループ
- 検索／ジャンプ

同じ機能へ両経路から到達できるようにする。

## 4. Progressive information

全数値を常時表示しない。

- 通常: 要約
- Hover / Focus: 詳細
- Advanced: 完全数値

必要な人だけ深く見られる。

## 5. Notifications

通知は出来事の数ではなく行動緊急度で分類する。

### Critical
即時対応が必要。

### Important
近いうちに見る。

### Log
記録だけ。

通知疲れを防ぐ。

## 6. Off-screen events

重要イベントが画面外で起きる場合、
- ミニマップ
- 音
- 通知
- カメラジャンプ
のどれかで気づけるようにする。

## 7. Automation

明白な反復操作は自動化してもよい。

ただし、
- 戦力配分
- 生産優先
- 攻撃判断
など、ゲームの中心判断まで自動化しない。

## 8. Information comfort

特にVR／モバイルでは、情報の存在位置と身体負担を一緒に考える。

「必要な情報を最短で、快適に得られるか」を見る。

## Playtest

- 戦闘中に資源状態も把握できるか
- 通知を無視する癖がついていないか
- 主要命令をUIとショートカット両方から出せるか
- 上級情報を隠しても初心者が困らないか
- 画面を横断する視線移動が多すぎないか
