# Audio as Gameplay

音を雰囲気づくりだけでなく、判断・空間認識・状態把握のための情報チャンネルとして設計する。

## 1. Audio can replace visual attention

画面上に表示しなくてもよい情報を音へ移す。

候補:
- 敵接近
- 残り時間
- リロード完了
- 危険方向
- アイテム接近
- 状態変化

目的はHUDを消すことではなく、視線を戦闘・移動へ残すこと。

## 2. Priority hierarchy

すべての音を同じ強さで鳴らさない。

優先順位:
1. 即時危険
2. 自分の状態
3. 成功／失敗
4. 環境情報
5. 雰囲気
6. 装飾

高優先音はBGMや連続SEに埋もれないようにする。

## 3. Direction and distance

音で空間を拡張する。

伝えられる情報:
- 左右
- 遠近
- 接近
- 高低
- 壁越し

ただしスマホのモノラル再生や小音量でも成立するよう、音色・間隔・画面補助も併用する。

## 4. State-dependent sound

同じ敵でも状態に応じて音を変える。

例:
- 通常
- 攻撃準備
- 追跡
- スタン
- 瀕死

視覚だけに依存せず、戦況を耳で追えるようにする。

## 5. Silence is information

BGM停止、環境音の減少、突然の静けさも情報になる。

常に音を足すのではなく、音を引くことで注意を作る。

## 6. Repetition fatigue

高頻度SEは短時間で疲労する。

確認:
- 連射音
- 被弾音
- UI決定音
- 低HP警告
- 足音

頻繁な音ほど短く、刺激を抑え、バリエーションを持たせる。

## 7. Mobile constraints

iPhoneなどでは、
- 小型スピーカー
- モノラルに近い聴取
- 無音プレイ
があり得る。

重要情報は音だけに依存しない。
ただし音をONにすると判断が速くなる設計は有効。

## Playtest

- 画面を見ずに危険接近を判断できるか
- 音を消しても最低限遊べるか
- 音をONにすると判断速度が上がるか
- 最重要警告音がBGMに埋もれないか
- 同じSEを5分聞いて疲れないか
